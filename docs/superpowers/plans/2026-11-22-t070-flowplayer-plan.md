# T-070 FlowPlayer: plan

Ledger task: T-070 (Phase 6). Spec [[2026-11-22-flow-design]] is binding; decision [[ADR-017 Flows as YAML content]]. This plan splits it into three tasks. T-071 (animation) gets its own plan after this PR merges.

**Global constraints (apply to every task).**

- Content rules (CLAUDE.md): public sources only, base ISO 20022 only (no CBPR+), own wording (never copy or closely paraphrase an ISO definition or a source sentence), synthetic data only. Say nothing the schema JSON, lesson 4 (`src/content/lessons/en/follow-the-flow.md`) or a source already cited there does not support. Cover is an outline: only the claims lesson 4 makes. Generated files (`src/data/schema/*.json`) are never hand-edited.
- Plain English for a new bank employee: short sentences, define a term at first use. Every flow text is AI-drafted: `lastReviewed.by` = `unreviewed (AI-drafted, pending T-093)` and a visible draft notice on the page (reuse the wording of `lesson.draft` under a new key).
- Every new check is shown failing once against a deliberate break, then restored (say how in the report). Browser checks wait with `settled()` from `scripts/ui-wait.ts` before reading position, focus, scroll or text after an action; a check must be able to fail (no `|| true`, no swallowed timeouts).
- UI: invoke `frontend-design:frontend-design`; text only through `t()` and `src/i18n/ui.en.json`; keyboard operable; state never by colour alone; passes axe at 1280 and 390px; use existing tokens (`text-muted`, `border-line`, `bg-surface`, `accent`, see `src/styles/global.css`); all hrefs via `BASE_URL`. Page JS budget 100 KB gzip (`npm run check:size`).
- Conventional Commits (`feat:`, `content:`, `test:`, `docs:`), small commits, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Stage specific files only (about ten `docs/` files show modified from CRLF only: never stage them).
- Before reporting run `npm test`, `npm run lint`, `npm run format:check`, `npm run build`, `npm run check:size`, `npm run check:a11y`, `npm run check:ui` and read the whole output for FAIL lines (`check:ui` and `check:a11y` read `dist`, so build first). New unit test files must be added to the `test` script in `package.json`.

## Task 1: Flow data, schema, content checks and the pacs.008 flow

Files: `src/lib/content-schemas.ts` (+ `content-schemas.test.ts`), `src/content.config.ts`, `scripts/check-content.ts` (+ `check-content.test.ts`), `src/content/flows/pacs.008-agent-chain.yaml`, `docs/sources.md` (only if a new source is read).

1. `FlowSchema` (strict zod) exactly as in the spec's Data paragraph: `id`, `message`, `title`, `summary`, `lesson`, `sample`, `sources` (same shape as lessons, https, min 1), `lastReviewed`, `participants[]` (`id`, `role`, `who`; at least 2), `variants[]` (`id` enum `serial|cover`, `title`, `intro`, `notice` optional, `steps[]` at least 2; step: `from`, `to`, `title`, `text`, `message?`, `elements?` default [], `settlement?`). Variant ids unique. Tests: accepts a good flow; rejects a missing `variants`, an unknown variant id, a non-https source, an extra key.
2. `content.config.ts`: `flows` collection (yaml loader, `src/content/flows`).
3. `check-content.ts`: load `flows/*.yaml` (the same way samples load), validate, and enforce the rules in the spec's "check-content rules" paragraph: id matches file name; `message` has a schema; every `elements` path resolves (use the existing `resolvePath`); every `settlement` is a code listed for `SettlementMethod1Code` in the schema JSON (read the code list from the schema, not from the overlay); `from`/`to` are participant ids; in each variant every participant is `from` or `to` of at least one step; `lesson` is a lesson id and `sample` a sample id of that message; variant ids unique. Print `Flows: N`. Unit tests for each rule, each shown failing once.
4. `src/content/flows/pacs.008-agent-chain.yaml`: participants `debtor` (role Debtor, who `Sample Importer Ltd`), `debtorAgent` (Debtor agent, `TESTGB2LXXX`), `intermediary` (Intermediary agent, `TESTUS33XXX`), `creditorAgent` (Creditor agent, `TESTDEFFXXX`), `creditor` (Creditor, `Sample Supplier GmbH`). `lesson: follow-the-flow`, `sample: pacs.008-intermediary`. Sources: the three lesson 4 sources (same URLs, retrieved dates) plus any you read.
   - Variant `serial` (intro: each bank sends its own pacs.008 to the next one), steps: (1) debtor to debtorAgent: the customer asks their bank to pay (say plainly this instruction is outside this site; no message name unless lesson 4 supports it); (2) debtorAgent to intermediary: the first pacs.008, message label "pacs.008 #1", elements `GrpHdr/MsgId`, `GrpHdr/SttlmInf/SttlmMtd`, `CdtTrfTxInf/PmtId/EndToEndId`, `CdtTrfTxInf/PmtId/UETR`, `CdtTrfTxInf/InstgAgt`, `CdtTrfTxInf/InstdAgt`, `CdtTrfTxInf/IntrmyAgt1`, settlement `INDA` (this is sample 2; say the intermediary settles by debiting the debtor agent's account with it, as the sample's scenario says); (3) intermediary to creditorAgent: a new pacs.008 "pacs.008 #2" with a new `MsgId`, the same `EndToEndId` and `UETR`, the intermediary now the instructing agent; say the settlement code on this hop depends on how those two banks settle and list the four schema codes in the text without choosing one (no `settlement` field here); (4) creditorAgent to creditor: the creditor agent credits the creditor (state it as the end of the chain; no booking detail).
   - Variant `cover` (intro, plus `notice`: this outline rests on public sources weaker than the schema, see lesson 4), steps: (1) debtor to debtorAgent as above; (2) debtorAgent to creditorAgent: the customer payment message goes toward the creditor agent, label "pacs.008", elements `GrpHdr/SttlmInf/SttlmMtd` with settlement `COVE`; it does not itself move the funds between the banks in the chain; (3) debtorAgent to intermediary: a second message, the cover payment, tells the banks in between to move the funds (label "cover payment"; say public sources point to a `pacs.009` usage and that we did not read a source setting it out in ISO 20022 terms); (4) intermediary to creditorAgent: the funds arrive through the banks in between (no more detail); (5) creditorAgent to creditor: the creditor agent matches the two messages (amount, currency, date, as lesson 4 says) and credits the creditor. Use `from == to` only if a step has no travel; none is needed here.
   - Text per step 1 to 3 short sentences, own wording, consistent with lesson 4; do not contradict it.

Done when: `npm run check:content` prints `Flows: 1`, breaking an element path, a settlement code or dropping a participant from every step fails it, and all local checks pass.

## Task 2: flow logic, FlowPlayer and the page

Files: `src/lib/flow.ts` (+ `flow.test.ts`, added to the `test` script), `src/components/FlowPlayer.tsx`, `src/pages/flows/[id].astro`, `src/i18n/ui.en.json`, `src/styles/global.css` only if needed.

1. `flow.ts` (pure, no Preact): `parseHash(hash, variantIds, stepCount: (variantId) => number)` returns `{variant, step}` (zero-based step), falling back to the first variant and step on anything invalid (`#cover/3` is variant `cover`, step index 2; `#serial`, `#x`, `#serial/0`, `#serial/99` fall back to step 0 of that variant if the variant is valid, else the first); `toHash(variant, step)`; `clampStep(step, count)`. Tests for each, each shown failing once.
2. `FlowPlayer.tsx` per the spec's "FlowPlayer UI". Props: the flow data (variants, participants), labels, the settlement code wording (a `Record<code, string>` from the overlay `codes.SettlementMethod1Code`, passed by the page), element link base, sample link. `TabList` from `src/components/ui/Tabs.tsx` for the variants. Desktop diagram `hidden md:block`, mobile list `md:hidden`, detail card and controls at both widths. Sender/Receiver words on the cards (not colour only). The detail card is `aria-live="polite"`; Previous/Next use `aria-disabled` at the ends. Hash read in `useEffect` after mount (server and first client render must match), written with `history.replaceState`. No animation in this task.
3. Page `/flows/[id].astro` (`getStaticPaths` over the `flows` collection): title, summary, draft notice, FlowPlayer, "Read lesson 4" link to the lesson, Sources list (like the lesson page), link back to all lessons. Indexed by Pagefind. All text through `t()`.

Done when: `/flows/pacs.008-agent-chain/` builds, stepping with Next reaches the last step and shows every participant as sender or receiver at some step, and all local checks pass.
