## Task 1: data format, content, rules, scoring logic

**Files:** `src/lib/content-schemas.ts`, `src/lib/content-schemas.test.ts`, `src/content.config.ts`, `src/content/quizzes/pacs.008.yaml` (new), `scripts/check-content.ts`, `scripts/check-content.test.ts`, `src/lib/quiz.ts` and `src/lib/quiz.test.ts` (new), `package.json` (add `src/lib/quiz.test.ts` to the `test` script).

1. `QuizSchema` (strict) per the spec, in the style of `FlowSchema`/`MappingSchema`/`GlossarySchema`: `id`, `message`, `title`, `summary`, `lesson`, `lastReviewed` (`Reviewed`), `questions` (min 1) of `{id, prompt, options (3 to 4 strings, min length 1), answer (int >= 0), explanation (min 1), lesson?, elements (default [])}`. A `quizzes` collection in `src/content.config.ts` (the `yaml()` loader, `src/content/quizzes`). Schema tests: accepts a valid quiz; rejects an unknown key, two options, empty explanation.
2. check-content rules per the spec (add `quizzes?: File[]` to `Input`, load in the CLI, print `Quizzes: N`), each with a test that a deliberately broken quiz fails it: file parses; id matches file name; `message` has a schema; `lesson` (quiz and question) exists; element paths resolve; `answer` < `options.length`; options distinct within a question; question ids unique; right answers not all the same index (only when there are at least 3 questions). Show each new rule failing once on real data, then restored (break and error text in your report).
3. `src/lib/quiz.ts`: `score(questions, picks)` as in the spec (`picks` is an array the length of the questions with a chosen index or `undefined`; a pick out of range counts as `skipped`). Pure, typed, no DOM. Tests: all right, one wrong, none picked, an out-of-range pick, empty question list, `picks` shorter than the questions. Show a test failing once (break the comparison).
4. `src/content/quizzes/pacs.008.yaml`: `id: pacs.008`, `message: pacs.008.001.14`, `lesson: check-yourself`, `lastReviewed: {date: "2026-11-23", by: "unreviewed (AI-drafted, pending T-093)"}`, title and summary of your wording, and eight questions, one per question of `src/content/lessons/en/check-yourself.md`, in that order, as multiple choice (3 or 4 options each). Source of each right answer: the lesson's own answer text, which cites lessons 1 to 5; read those lessons and the schema before writing, and keep each explanation to the facts they state. Give each question a `lesson` (the lesson its answer comes from) and `elements` where the question names elements (for example `CdtTrfTxInf/RmtInf/Ustrd` for question 8; verify each path resolves). Vary the position of the right answer. Distractors: plausible to a beginner, wrong by the lessons or schema (for example the opposite of the right claim, or swapping debtor and creditor agent), never a different-but-defensible reading. In your report, list per question which lesson sentence or schema fact supports the right answer and why each distractor is wrong.
